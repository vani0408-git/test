RAG Mental Model

What each stage is doing
1Documents

RAG starts with knowledge: PDFs, policies, websites, databases, manuals, emails, or other content.

2Validation & Cleaning

Remove empty content, formatting noise, duplicates, broken text, headers, footers, and irrelevant data.

3Chunking

Large documents are split into smaller pieces. Chunk size and overlap strongly affect retrieval quality.

4Embeddings

An embedding model converts each chunk into a numeric vector representing semantic meaning.

5Query Embedding

The user's question is converted into a vector using the same embedding space.

6Retrieval

Vector similarity search finds chunks whose meaning is closest to the user's query. Real systems may also use filters, hybrid search, and reranking.

7Augmentation

Retrieved chunks are inserted into the prompt together with system instructions and the user's question.

8Generation

The LLM generates an answer based on the question and retrieved knowledge.

Important Gaps Filled

Real-world RAG concepts
Embedding ≠ vector search.

The embedding model creates vectors. The vector database searches those vectors.
Retrieval happens before generation.

The vector database does not normally generate the answer. Its job is to retrieve useful context.
Production systems often add reranking.

Initial search may retrieve 20 candidates, then a reranker selects the best few for the LLM.
Metadata matters.

Chunks may carry document name, page number, department, permissions, dates, product names, and other filtering information.
RAG can still fail.

Bad chunking, poor retrieval, stale documents, weak prompts, or missing source material can still produce an incorrect answer.
